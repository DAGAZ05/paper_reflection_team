

# 复核决策逻辑评估规则



## 壹

### 人工复核标记规则

#### 一、标记核心原则

基于逻辑、文献、代码、实验、格式五大审计组输出结果的置信度与多组结论冲突性双维度判定，兼顾审稿准确性与人工复核效率，杜绝错判、漏判及无意义的人工复核工作，适配软件工程硕士毕业论文智能审稿场景。

#### 二、触发条件（满足任一条件即标记为“需人工复核”）

1. **置信度阈值触发**：单条审计建议的系统置信度评分＜0.7（置信度由各个审计组输出）；
2. **多组冲突触发**：≥2 个审计组针对论文同一审核点，提出相互矛盾 or 相悖的审计结论；
3. **结果存疑触发**：审计组输出结果未标注置信度、未提供核心证据支撑（如仅标注 Critical 等级但未引用原文 or 指明具体问题位置）。

#### 三、标记类型与字段规范

##### （一）标记类型

|    标记类型    |          对应触发条件          | 复核优先级 |
| :------------: | :----------------------------: | :--------: |
|    Conf_Low    |          置信度＜0.7           |     中     |
| Agent_Conflict |     多组结论冲突（≥2 组）      |     高     |
|  Evid_Missing  | 无置信度评估 or 无核心证据支撑 |     中     |

##### （二）标准标记字段（适配项目接口规范）

```json
{
  "review_mark_id": "唯一标记ID（格式：RM-年月日-序号，如RM-20260214-001）",
  "audit_point": "论文具体审核点（如1.1章节核心算法性能/参考文献[12]真实性）",
  "related_agents": ["涉及的审计组英文标识（如Logic_Audit, Code_Audit）"],
  "mark_type": "标记类型（Conf_Low/Agent_Conflict/Evid_Missing）",
  "trigger_reason": "标记触发详细原因（精准描述冲突点/置信度问题/证据缺失情况）",
  "confidence_scores": {"审计组英文标识": 置信度数值（如"Code_Audit":0.65）},
  "mark_priority": "复核优先级（高/中/低）",
  "related_result_ids": ["各审计组对应结果的唯一ID"]
}
```

#### 四、复核结果回写规则

人工完成复核后，需在原标记 JSON 字段中补充以下 3 个字段，实现标记全流程可追溯：

1. `manual_review_result`：复核结论（保留原审计结果 or 修正审计结果 or 剔除无效结果）；
2. `manual_reviewer`：复核人标识 or 姓名；
3. `review_time`：复核完成时间（格式：YYYY-MM-DD HH:MM:SS）。





## 贰

### 审计建议优先级排序权重表

#### 一、核心排序逻辑

以**审计问题等级基础权重**为核心，叠加**问题影响范围附加权重**，通过量化公式计算单条审计建议的排序得分，得分从高到低对应优先级从高到低，公式为：

**排序得分 = 基础权重 ×（1 + 附加权重）**

#### 二、基础权重（按问题本身的严重程度划分）

参考 Nature/IEEE 顶级期刊审稿标准制定，为优先级排序的核心依据，等级定义与各审计组保持一致。

| 问题等级 |                核心定义                 | 基础权重 |                 典型问题示例                 |
| :------: | :-------------------------------------: | :------: | :------------------------------------------: |
| Critical | 致命问题，直接影响论文核心结论 / 科学性 |   1.0    |     逻辑矛盾、伪造参考文献、代码致命漏洞     |
|  Major   |  主要问题，需大幅修改但不影响核心结论   |   0.6    | 实验样本量不足、引用格式不统一、算法优化缺陷 |
|  Minor   | 次要问题，简单修改即可修正，无实质影响  |   0.2    |  术语拼写错误、标题层级瑕疵、代码命名不规范  |

#### 三、附加权重（按问题对论文的影响范围划分）

附加权重取值 0-0.3，仅对基础权重做增量调整，不改变基础等级的核心排序逻辑，精准匹配软工硕士论文的结构与审稿重点。

|    影响范围    | 附加权重 |                 适用场景                  |
| :------------: | :------: | :---------------------------------------: |
|  论文核心部分  |   0.3    | 涉及摘要、结论、核心实验、核心算法的问题  |
| 论文非核心部分 |   0.1    |  涉及参考文献列表、附录、图表注释的问题   |
|   无明确范围   |   0.0    | 未标注具体位置 / 跨章节但无核心影响的问题 |

#### 四、特殊场景排序规则

1. **多组同点问题**：同一审核点被多个审计组标记问题时，取**最高问题等级**的基础权重计算得分，附加权重直接取 0.3（默认影响论文核心）；
2. **已标记人工复核的问题**：需人工复核的审计建议，**暂排所有未标记问题之前**，待复核完成后按最终结论重新计算得分排序；
3. **无等级标注的问题**：默认按 Minor 等级（基础权重 0.2）计算，附加权重 0.0，且在同得分建议中排最后。

#### 五、示例

1. 摘要中算法结论的逻辑矛盾（Critical & 核心）：1.0×(1+0.3)=1.3（最高优先级）；
2. 附录中代码变量命名不规范（Minor & 非核心）：0.2×(1+0.1)=0.22；
3. 实验章节样本量不足（Major & 核心）：0.6×(1+0.3)=0.78；
4. 参考文献格式不统一（Major & 非核心）：0.6×(1+0.1)=0.66。





## 叁

### 复核决策逻辑设计稿

#### 文档基础信息

- 文档版本：V1.0
- 设计人：反思评估组成员 D
- 设计日期：2026 年 02 月 13 日
- 适配场景：智能评估软件工程硕士毕业论文的审稿 Agent 系统 - 反思评估模块

#### 一、设计目标

1. 制定可执行、可量化、可扩展的人工复核标记与审计建议优先级排序逻辑，为后续模块开发提供核心依据；
2. 定义标准化的数据接口与 JSON 字段格式，实现与组内其他模块及五大审计组的交接；
3. 兼顾学术审稿专业性与工程开发效率，适配软工硕士毕业论文的审稿重点，兼容规则引擎、FastAPI 等技术栈开发要求。

#### 二、设计依据

1. 智能审稿 Agent 各小组职责清单（五大审计组核心职责、输出规范及标签定义）；
2. LLM-as-a-Judge 论文调研成果（量化评分、冲突裁决的通用逻辑与落地方案）；
4. 软件工程硕士毕业论文的审稿标准与核心关注要点。

#### 三、核心决策逻辑流程

本设计的核心逻辑分为**人工复核标记**与**审计建议优先级排序**两大模块，执行流程为**先标记，后排序**，确保未复核的存疑建议优先处理，具体逻辑如下：

1. 接收五大审计组的审计结果集合，按《人工复核标记规则》逐一条判定是否触发人工复核，生成标准化标记结果；
2. 对所有审计建议（含已标记、未标记），按《优先级排序权重表》的量化公式计算排序得分；
3. 按 “已标记复核建议暂排前列→未标记建议按得分从高到低” 的规则完成最终排序，生成结构化排序结果；
4. 人工复核完成后，将复核结论回写至标记字段，并重新计算修正后建议的排序得分，更新排序结果。

#### 四、数据接口定义（JSON Schema，适配 FastAPI 开发）

##### （一）输入接口：接收各审计组结果

- 接口类型：POST
- 接口地址：/reflection/audit/input
- 接口描述：接收五大审计组对单篇论文的审计结果集合，为复核标记与优先级排序提供原始数据
- 入参格式（JSON）：

```json
{
  "paper_id": "论文唯一标识（项目统一格式）",
  "paper_topic": "软件工程硕士毕业论文题目",
  "audit_results": [
    {
      "audit_agent": "审计组英文标识（Logic_Audit/Code_Audit等）",
      "result_id": "审计结果唯一ID（项目统一格式）",
      "audit_point": "论文具体审核点",
      "problem_level": "问题等级（Critical/Major/Minor/None）",
      "confidence": 0.0-1.0（置信度数值，保留2位小数）,
      "evidence": "问题核心证据（原文引用/具体位置描述）",
      "tags": ["审计组专属标签（如Logic_Leap/Syntax_Error）"],
      "audit_time": "审计完成时间（YYYY-MM-DD HH:MM:SS）"
    }
  ]
}
```

##### （二）输出接口：返回复核标记 + 优先级排序结果

- 接口类型：GET
- 接口地址：/reflection/audit/output
- 接口描述：返回单篇论文的人工复核标记结果与审计建议优先级排序结果，为导师对话生成、系统总调度提供数据支撑
- 出参格式（JSON）：

```json
{
  "paper_id": "论文唯一标识",
  "review_mark_results": [{"人工复核标记结果（按交付物1字段规范）"}],
  "sorted_audit_results": [
    {
      "result_id": "审计结果唯一ID",
      "audit_agent": "审计组英文标识",
      "audit_point": "论文具体审核点",
      "problem_level": "问题等级",
      "sort_score": 0.00（排序得分，保留2位小数）,
      "mark_status": "是否标记复核（是/否）",
      "priority_rank": 排序排名（正整数）
    }
  ],
  "generate_time": "结果生成时间（YYYY-MM-DD HH:MM:SS）",
  "version": "设计稿版本（V1.0）"
}
```

#### 五、设计合理性评估

1. 量化性：将模糊的 “修改必要性” 转化为可计算的排序得分，避免主观判断，适配算法开发与工程落地；
2. 兼容性：标记规则与排序逻辑适配所有审计组的输出规范，无审计组专属限制，支持后续审计组扩展；
3. 可调整性：置信度阈值、权重系数、标记触发条件均可动态配置，可根据后续测试结果与审稿需求灵活优化；
4. 专业性：参考顶级期刊与软工硕士毕业论文的审稿标准，确保逻辑贴合学术审稿的实际需求，避免脱离场景。
