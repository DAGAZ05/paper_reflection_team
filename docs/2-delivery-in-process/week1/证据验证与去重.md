## 1）证据验证：双通道选型
我们要解决的问题很单一：对每条“上游Agent给出的引用/结论”，判断它在论文原文里是否真的能找到对应证据，并且返回可解释的定位信息（在哪个 section/段落）。为了保证“准”和“能覆盖改写”，采用双通道：

第一通道走精确匹配，用来处理“逐字引用”或“轻微标点/空白差异”的情况。这条通道优势是准确率高、解释性强；命中后直接给高置信度，并把命中的原文片段和位置返回。

第二通道走语义匹配，仅在精确不命中时启用，用来兜底“同义转述/改写总结”的情况。实现上不做全篇暴力对比，而是先在段落级做 Top-K 召回，再对候选做阈值判断与轻量规则约束，避免泛化语句误报。

最小可落地实现（V1.0）就是：

- 论文按 section→paragraph 切分；
- 先做精确匹配（规范化后包含判断/轻量编辑距离）；
- 精确未命中则做语义检索（向量化 paragraph，余弦相似 Top-K）；
- 语义候选通过阈值后，再做“数字一致性/关键术语一致性”两条轻规则校验；
- 输出 exists/method/confidence/evidence_spans/matched_text。

## 2）阈值与置信度口径
### 2.1 阈值
精确匹配：

- 规范化（去空白、统一全半角、去常见标点差异）后，如果 `quote` 被原文段落包含，则视为命中。
- 若使用编辑距离（可选），允许小幅差异：差异率 ≤ 2% 仍视为命中。

语义匹配（余弦相似度）：

- 默认 `semantic_threshold = 0.86`。
- `top_k = 5`（长文可调到 8）。

DBSCAN 去重阈值单独在第3部分给出。

### 2.2 置信度计算
为了便于解释与下游加权，V1.0 不做“花哨融合”，而是采用分段置信度：

- 若精确命中：
  - `confidence = 0.97`（逐字包含）
  - `confidence = 0.92`（编辑距离命中，差异率≤2%）

- 若语义命中：
  - 先取 `sim`（0~1）作为基础
  - 再乘以规则因子 `rule_factor`（默认 1.0，触发约束则下调）
  - `confidence = clip(sim * rule_factor, 0, 0.90)`，并把 `method=semantic`

规则因子（可开关，建议默认开启）：

- 数字一致性（enable_numeric_check）：如果 claim/quote 含数字，但候选段落缺失相同数字（或近似格式），`rule_factor *= 0.6`。
- 关键术语一致性（enable_term_check）：如果 claim/quote 含方法名/数据集名/专有名词（用小词典或简单正则抽取即可），候选段落缺失关键术语，`rule_factor *= 0.7`。

这样做的好处是：语义兜底仍然能用，但系统会显式告诉下游“这是语义命中且置信度被约束下调”，便于成员A/成员D制定更谨慎的复核策略。

## 3）去重聚类：Sentence-Transformers + DBSCAN
V1.0 方案：

- 对每条建议文本（item.text）用 Sentence-Transformers 编码成向量；
- 使用余弦距离 `distance = 1 - cosine_similarity`；
- DBSCAN 做无监督聚类（不需要预设簇数，适合建议数量波动）。

参数建议（V1.0默认）：

- `min_samples = 2`（两条相似就形成重复簇）
- `eps = 0.16`（约对应相似度 0.84 左右；可在 0.12~0.20 区间小步调参）

输出结构（给下游直接用）：

- `cluster_id`
- `representative_item`：代表建议（取簇内“平均距离最小”的条目即可）
- `members`：簇内原始条目（保留 agent 名与原文）
- `cluster_stats`：簇大小、涉及 agent 集合、平均相似度

这套去重实现非常“工程友好”：只依赖向量编码 + DBSCAN，效果不好就调 eps；同时保留 members，确保不会因为去重导致信息不可追溯。

## 4）接口草案
下面是 V1.0 的接口字段草案，重点是“字段少但够用”，能让第2周直接开写。

### 4.1 EvidenceValidationRequest
```json
{
  "paper_id": "uuid",
  "paper_field": "软件工程",
  "sections": [
    {
      "section_id": "3.2",
      "title": "Method",
      "paragraphs": ["段落1...", "段落2..."],
      "offset": 12345
    }
  ],
  "items": [
    {
      "item_id": "uuid",
      "agent": "method_agent",
      "claim_text": "作者采用XX方法，在YY数据集上提升12%",
      "quote": "可选：逐字引用",
      "evidence_hint": "可选：见第3节/表2",
      "upstream_confidence": 0.72
    }
  ],
  "config": {
    "top_k": 5,
    "semantic_threshold": 0.86,
    "enable_numeric_check": true,
    "enable_term_check": true
  }
}
```

### 4.2 EvidenceValidationResult
```json
{
  "item_id": "uuid",
  "exists": true,
  "method": "exact",
  "confidence": 0.97,
  "evidence_spans": [
    {
      "section_id": "3.2",
      "paragraph_index": 1,
      "char_start": 120,
      "char_end": 188
    }
  ],
  "matched_text": "命中的论文原文片段（可截断）",
  "notes": "逐字包含（忽略标点差异）"
}
```

### 4.3 DedupRequest / DedupResult
```json
{
  "paper_id": "uuid",
  "items": [
    {
      "item_id": "uuid",
      "agent": "writing_agent",
      "text": "建议补充实验设置细节以增强可复现性"
    }
  ],
  "config": {
    "eps": 0.16,
    "min_samples": 2
  }
}
```
